# RAG 파이프라인 설계

## 데이터와 메타데이터 색인

1. `1_index_meta.py`가 `dataset/gym_exercises.csv`를 읽고 `dropna()`로 결측치가 있는 행을 모두 제외합니다.
2. 운동명과 설명은 영어 원문으로 유지하고, 유형·부위·기구·난이도는 화면과 문서에 사용할 한글 값으로 매핑합니다.
3. 각 행을 운동명, 유형, 자극 부위, 필요 기구, 난이도, 설명을 포함하는 LangChain `Document`로 만듭니다. 메타데이터에는 출처 종류와 제목이 들어갑니다.
4. `text-embedding-3-small` 임베딩으로 `exercise_meta` Chroma 컬렉션을 `chroma_meta_db/`에 저장합니다.

현재 CSV에서 `dropna()` 이후 501행이 남습니다. 컬럼 전체를 기준으로 제거하므로 평점 등 앱에서 사용하지 않는 값의 결측도 제외에 영향을 줍니다.

## 질문 처리

앱의 LangGraph는 `retrieve`와 `generate` 두 노드로 구성됩니다.

### 운동 추천 질문

1. `analyze_user_question`이 LLM과 규칙 기반 별칭으로 의도, 부위, 난이도, 기구 조건을 분석합니다.
2. `find_matching_exercises`가 CSV의 영어 속성을 기준으로 조건을 정확히 필터링하고, 부위별로 번갈아 최대 6개 후보를 선택합니다.
3. CSV 행을 근거 자료로 구성한 후 추천 프롬프트가 해당 자료만 사용하도록 답변을 생성합니다.

이 추천 경로는 벡터 유사도 검색을 사용하지 않습니다.

### 운동 지식 질문

1. 분석된 영어 검색어로 영구 `exercise_meta` 컬렉션에서 유사 문서 최대 5개를 조회합니다.
2. 한국어 위키백과에서 검색 결과 최대 3개를 가져오고, 첫 번째 문서의 본문을 조회합니다.
3. 위키 본문을 800자 청크와 150자 중복으로 나누고, 질문별 임시 Chroma 저장소에서 최대 2개 청크를 검색합니다.
4. 운동 메타데이터와 위키 결과를 하나의 근거 목록으로 합쳐 `generate` 노드에 전달합니다.
5. 답변 프롬프트는 제공된 근거만 사용하도록 안내하며, `[근거 N]` 형식의 인용을 UI가 실제 출처 목록과 연결합니다.

위키 문서는 영구 색인에 저장되지 않고 질문마다 다시 수집·임베딩됩니다. 메타데이터 검색 수, 위키 청크 수, 청크 크기는 현재 코드에 고정되어 있습니다.

### 루틴 생성

루틴 화면은 사용자의 횟수·경력·운동 시간·추가 목표를 LLM에 전달해 표 형태의 초안을 생성합니다. 이 경로에는 검색 노드나 근거 인용이 없으므로 검색 기반 RAG 기능과 별도로 취급해야 합니다.

## 현재 구현에서 확인된 개선 항목

- 재색인 시 기존 컬렉션을 초기화하거나 결정적인 ID로 중복을 방지하지 않습니다.
- CSV 전체 컬럼에 `dropna()`를 적용해 사용 가능한 행이 501개로 줄어듭니다.
- 외부 위키 HTTP 요청에 타임아웃이 없습니다.
- 위키 자료를 질문마다 새로 임베딩하며, 검색 점수·중복 제거 과정을 사용자 설정으로 조정할 수 없습니다.
- MMR, RAG 사용 전후 답변 비교, 평가 데이터셋이 구현되어 있지 않습니다.
- 루틴 추천은 검색 근거에 기반하지 않습니다.
