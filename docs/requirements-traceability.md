# 요구사항 추적표

기준 문서: `AI코어프로젝트_2회차_요구사항정의서.pdf`의 F2001~F2016 및 NF2001~NF2007. 상태는 현재 확인한 코드 기준이며, 완료 상태는 실행 검증과 별도로 판단했습니다.

상태: **확인**은 코드 경로가 있음, **부분**은 일부 조건만 충족하거나 검증이 더 필요함, **미구현**은 코드에서 확인하지 못함을 의미합니다.

## 기능 요구사항

| ID | 요구사항 요약 | 상태 | 코드 근거 및 메모 |
| --- | --- | --- | --- |
| F2001 | 선택 도메인의 메타데이터를 적재하고 문서로 구성 | 부분 | CSV 각 행을 `Document`로 구성합니다. 다만 전체 컬럼 `dropna()`로 2,918행 중 501행만 남습니다. |
| F2002 | 임베딩 후 Vector DB에 색인 | 부분 | `exercise_meta` Chroma 컬렉션에 저장합니다. 기존 컬렉션 초기화나 결정적 ID가 없어 반복 실행 중복을 방지하지 못합니다. |
| F2003 | 질문에서 검색어를 추출하는 프롬프트 | 확인 | 질문을 분석해 영어 검색어와 한국어 위키 검색어를 생성합니다. |
| F2004 | 외부 문서를 검색·선별하고 본문과 출처 수집 | 부분 | 한국어 위키백과에서 검색하고 첫 결과 문서 본문과 URL을 가져옵니다. 후보 선별 기준은 별도 점수화하지 않습니다. |
| F2005 | 외부 문서 청킹 및 별도 색인 | 부분 | 위키 텍스트를 800자/150자 중복으로 나눠 임시 Chroma에 임베딩합니다. 영구 별도 컬렉션은 아닙니다. |
| F2006 | 두 컬렉션 검색 결과 병합, 중복 제거, Top-k 설정 | 부분 | 메타데이터 최대 5개와 위키 청크 최대 2개를 합칩니다. 중복 제거 및 설정 파일 기반 Top-k 조절은 없습니다. |
| F2007 | LangGraph 노드로 검색과 답변 생성 구성 | 확인 | `retrieve`와 `generate` 두 노드로 구성되어 있습니다. |
| F2008 | 실제 사용 근거의 번호·출처 표시, 근거 없을 때 안내 | 확인 | 인용 번호를 출처 목록과 연결하고, 검색 자료가 없으면 안내 답변을 반환합니다. |
| F2009 | 도메인 항목 탐색 및 상세 정보 확인 | 확인 | 부위와 운동명을 선택해 난이도, 기구, 설명을 표시합니다. |
| F2010 | 도메인 특화 기능을 근거와 함께 제공 | 부분 | 조건 기반 추천은 CSV 후보에 근거하지만, 루틴 생성은 검색 문서 없이 LLM으로 작성합니다. |
| F2011 | 자연어 조건에 맞는 항목 검색 | 확인 | 부위·난이도·기구 조건을 CSV 영문 값으로 정규화해 필터링합니다. |
| F2012 | 처리 상태, 오류, 위험 도메인 안내 | 부분 | 질문 처리 상태와 의료 안내가 있습니다. 예외별 안내가 일관되지는 않고 위키 오류는 조용히 무시됩니다. |
| F2013 | HTML/CSS/JavaScript 프론트엔드와 서버/API 분리 | 부분 | Streamlit이 UI와 서버 실행을 제공합니다. 직접 구현한 별도 프론트엔드 및 API 계약은 없습니다. |
| F2014 | 유사도 검색 대신 MMR 적용 | 미구현 | `similarity_search`를 사용하며 MMR 경로를 확인하지 못했습니다. |
| F2015 | 동일 질문의 RAG 전후 답변 품질 비교 | 미구현 | 비교 실행, 평가 기록, 결과 문서가 없습니다. |
| F2016 | 서로 다른 출처 유형을 함께 검색하고 구분 표시 | 부분 | 지식 질문에서 운동 데이터와 위키 결과를 합치고 유형을 표시합니다. PDF 출처 수집은 없으며 추천 경로는 CSV만 사용합니다. |

## 비기능 요구사항

| ID | 요구사항 요약 | 상태 | 코드 근거 및 메모 |
| --- | --- | --- | --- |
| NF2001 | 대표 질문 처리 중 앱 응답이 멈추지 않음 | 부분 | HTTP 요청에 timeout이 없고 외부 API·LLM 지연 상황의 검증 기록이 없습니다. |
| NF2002 | 이미 수집·색인한 자료를 불필요하게 재수집하지 않음 | 부분 | CSV·모델·Vector DB는 Streamlit 캐시를 사용합니다. 위키 문서는 질문마다 다시 수집·임베딩합니다. |
| NF2003 | API 키를 환경변수로 관리하고 소스에 포함하지 않음 | 확인 | `GMS_KEY`를 환경에서 읽고 `.env`를 사용합니다. 실제 배포 설정과 저장소 제외 여부는 별도 확인이 필요합니다. |
| NF2004 | 화면·로그에 키, 프롬프트, 개인정보 등 내부정보를 노출하지 않음 | 부분 | 키를 UI에 표시하지 않는 코드는 확인했습니다. 운영 로그·예외 화면의 노출 여부는 배포 환경에서 검증해야 합니다. |
| NF2005 | 수집·색인·검색·생성·UI 모듈 분리 | 부분 | 색인 스크립트는 분리되어 있으나 검색, 생성, UI가 `app.py`에 함께 있습니다. |
| NF2006 | 외부 API 예절과 User-Agent 연락처 준수 | 부분 | `WIKI_CONTACT` 기반 User-Agent가 있습니다. timeout, 호출 간격 제한은 확인되지 않았습니다. |
| NF2007 | 데이터·문서의 출처와 이용 조건 기록 | 부분 | 위키 URL은 답변 근거에 포함됩니다. Kaggle 데이터의 정확한 원본 URL·라이선스는 프로젝트 파일에서 확인되지 않았습니다. |

## 제출 전 우선 확인

1. CSV 원본 Kaggle URL, 작성자, 라이선스를 확인하고 README에 기록합니다.
2. 색인 결과 문서 수가 기대 행 수와 일치하는지 확인하고, 재실행 중복 방지 또는 안전한 재색인 절차를 마련합니다.
3. PDF 요구사항의 MMR, RAG 전후 비교, 응답 지연·캐시 검증을 구현하거나 미구현 사유와 범위를 제출 문서에 명시합니다.
4. 검색 근거 없이 생성되는 루틴의 범위를 명확히 하고, 근거 기반 루틴이 필요하면 검색 흐름과 인용을 연결합니다.
5. 실행 검증 결과와 화면 캡처는 [검증 체크리스트](verification-checklist.md)에 추가합니다.
