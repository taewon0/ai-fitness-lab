# 고정 501문서 CSV-RAG 평가·채점 기준 v1

작성: 2026-10-28. 검토 주체: Codex 에이전트.
사용자가 위임한 질문 설계·원문 검토·채점·집계를 에이전트가 수행한다.
독립적인 사람 또는 운동 전문가의 검증을 받았다는 의미는 아니다.
개별 건강 효과의 과학적 타당성을 입증하는 시험이 아니라 고정 코퍼스 기준 답변 평가다.

## 평가 범위와 데이터

- 기존 전처리·501문서를 변경하지 않는다.
- dev.jsonl: 20문항(답변 가능 16, 답변 불가 4).
- test.jsonl: 60문항(설명 36, 속성 4, 비교 5, 답변 불가 15).
- 개발셋은 16개 운동, 테스트셋은 40개 운동을 사용하며 source_id를 분리했다.
- 두 평가셋의 답변 가능 문항은 현재 코퍼스의 모든 16개 BodyPart 범주를 포함한다.
- 문항 비중은 수작업으로 설계한 커버리지이며 실제 사용자 질문 분포의 추정치가 아니다.
- 테스트 문항 60개가 모두 독립적인 운동을 다루지는 않는다. 비교·답변 불가 질문은 같은 운동을 재사용한다.
- seed 3문항은 연결 확인용이며 정식 테스트 점수에 섞지 않는다.
- 생성 모델: qwen3:8b-q4_K_M. 임베딩: bge-m3. 동일 질문·모델·옵션의 no_rag/rag 비교.
- 앱의 질의 분석·위키 실시간 검색·루틴·UI는 별도 범위다.

## 정답 근거

각 JSONL 문항은 reference_answer, required_facts, source_ids, reference_evidence를 가진다.
reference_evidence의 인용문은 eval/db/baseline/corpus.json의 해당 필드에서 그대로 가져왔다.
metadata 문항은 반드시 그 운동의 CSV 속성을 기준으로 채점한다.
원문 설명과 분류가 일반 운동 지식과 다를 수 있으므로, 코퍼스와 의학적 진실을 동일시하지 않는다.
근거가 충돌하면 임의로 하나를 사실로 확정하지 말고 충돌 사실과 한계를 기록한다.

한국어/영어 동의 표현은 허용한다.
예: 복근/복부 근육, 이두근/바이셉스, 삼두근/트라이셉스, 둔근/글루트, 비복근/gastrocnemius.
상완근(brachialis)과 이두근(biceps)은 이 평가에서 서로 대체하지 않는다.
핵심 의미가 같으면 정답 문구와 문자열이 정확히 같을 필요는 없다.

## review.csv의 3개 필드

### correct

1:
- 질문이 요구하는 required_facts를 모두 충족한다.
- 운동과 사실의 대응이 맞고 중대한 사실 오류가 없다.
- 핵심 답변에 영향을 주는, 근거로 뒷받침되지 않는 단정을 추가하지 않는다.
- 답변 불가 문항은 요청한 세부정보가 자료에 없음을 명확히 밝히고 값을 지어내지 않는다.

0:
- 필수 사실의 누락, 잘못된 부위·기구·수치, 비교 대상의 뒤바뀜.
- 다른 운동의 효과나 속성을 질문한 운동에 적용하는 중대한 전이.
- 원문의 “일부”, “가능성”, “perhaps”를 효과 보장으로 강화하는 경우.
- 답변 가능한 질문에 내용 없이 모른다고만 답함.
- 모른다고 말한 뒤에도 개인 중량·효과·기간 등의 값을 임의로 확정함.

근거 없는 모든 짧은 배경 문구를 곧바로 중대한 오류로 간주하지는 않는다.
정답 판단에 영향을 주는 주장인지 notes에 구체적으로 적는다.
불확실하면 0/1을 억지로 확정하지 않고 agent-review.json에 pending과 이유를 남긴다.
pending이 있으면 최종 확정 성과 수치를 발표하지 않는다. 현재 집계 도구도 미채점을 거부한다.

### unsupported

1: 검증된 정답 근거·원문 자료로 확인하지 못한 사실 주장을 하나 이상 포함함.
0: 추가 사실이 없거나, 모든 실질적 사실을 근거로 확인할 수 있음.

이는 사실이 반드시 거짓이라는 판정과는 다르다.
인용 번호가 없다는 이유만으로 1로 표시하지 않는다.
no_rag도 같은 정답 자료로 확인하며, 입력에 근거를 주지 않았다는 이유만으로 오답 처리하지 않는다.
rag의 경우 실제 제공된 문서가 그 주장을 뒷받침하는지도 별도로 본다.
어떤 사실이 실제로는 다른 문서에 있지만 검색되지 않았을 때는 그 차이를 notes에 적는다.

### abstained

1: 요청한 정보가 확인되지 않거나 자료가 부족하다고 명시적으로 보류함.
0: 그런 보류가 없음.
답변 가능 여부와 무관하게 실제 답변 행동을 기록한다.
모른다고 했다가 숫자를 지어낸 경우에도 abstained=1일 수 있지만 correct는 0이다.

## 인용 검토

기본 CSV 점수와 별도로 agent-review.json에서 기록한다.
- 번호가 실제 제공 자료의 범위 안에 있는지.
- 인용한 문서가 주장과 같은 운동을 설명하는지.
- 문서의 불확실성 표현을 보존하는지.
- 앱이 해석하는 [근거 1] 또는 [근거 1, 2] 형식인지.
- [근거 1-5]처럼 현재 앱이 해석하지 못하는 형식을 사용했는지.
- no_rag에서 실제로 제공하지 않은 문서 번호를 만들어냈는지.

인용 형식만 잘못된 경우 내용 정답률과 구분한다.
다른 운동의 효과를 붙이는 등 내용까지 달라지면 correct에도 반영한다.

## 검색 지표

relevant_groups는 반드시 확보해야 하는 근거 묶음들이다.
같은 묶음 내부의 ID는 같은 사실을 뒷받침하는 대체 문서다.
예: [[a,b],[c]]에서 a와 c를 검색하면 Recall=1이며, a와 b만 검색하면 Recall=0.5다.
Hit@k는 하나 이상의 필수 근거 그룹을 확보했는지, Recall@k는 그룹 중 확보한 비율이다.
대체 문서는 원문 설명이 같은 경우를 확인해 추가했다.
metadata 문항은 같은 설명이어도 난이도 등이 다를 수 있어 해당 source_id만 정답으로 쓴다.
이 규칙은 데이터 중복 제거가 아니라 평가 정답의 표현 방식이다.
relevant_groups가 없는 과거 문항은 원래대로 각 ID를 필수 근거로 취급한다.
답변 불가 문항과 no_rag에는 Hit/Recall을 부여하지 않는다.
정답 그룹이 완전하지 않으면 검색 점수가 과소평가될 수 있으므로 오류 사례를 검토한다.

## 검토 절차

1. 원본 answers.jsonl과 config.json을 보존한다.
2. method 열이 없는 review.csv를 먼저 보고 원문과 정답 기준으로 판정한다.
3. agent-review.json에 각 판단 근거와 인용 문제를 기록한다.
4. 실제 비교 조건을 확인해 동일 기준 적용 여부를 재검토한다.
5. correct/unsupported/abstained를 채운다. 사용자에게 수동 채점을 요구하지 않는다.
6. summarize를 실행하고 요약 수치를 원시 로그로 대조한다.
7. 오류율·출력 잘림·미채점 수를 함께 확인한다.

모델 출력의 인용 형식 때문에 조건을 추정할 수 있고, 원시 로그에도 방법 이름이 있다.
따라서 완전한 맹검 또는 독립 평가라고 표현하지 않는다.
초기 smoke는 답변을 본 뒤 기준을 정리한 탐색 검토다.
최종 test의 출력은 아직 보지 않은 상태에서 이 기준과 파일 해시를 고정한다.

## 집계와 해석

- 정확도는 전체 시도 중 엄격한 근거 기준으로 correct=1인 비율이다. API 오류도 분모에 포함한다.
- unsupported는 성공 응답 중 해당 플래그가 있는 비율이다. 주장 개수 기준 환각률이라고 부르지 않는다.
- 성공 응답의 시간과 오류를 포함한 시간은 구분한다.
- 첫 요청과 반복 요청의 모델 로딩·임베딩 비용이 다를 수 있다.
- 결과가 잘린 경우 제외하지 않고 기록한다.
- 반복 3회는 문항 수를 3배의 독립 표본으로 만드는 것이 아니다.
- 신뢰구간이 필요하면 질문/운동 군집을 고려한 paired bootstrap을 사용한다.
- 개발셋으로 설정을 조정한 뒤 고정 테스트셋으로 최종 평가한다.
- 같은 테스트셋을 반복해서 보며 유리한 설정을 고르지 않는다.
- 성과는 “로컬 CSV-RAG 후속 평가”로 표현하며 과거 GMS 서비스의 측정값으로 소급하지 않는다.
